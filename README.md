# 选课系统 · Course Selection System

> 软件工程课程作业 · 交付物包含**可运行系统**、**软件工程文档**与 **UML 图表**

---

## 一、项目简介

本项目为软件工程课程作业，围绕高校**选课业务**实现一套完整的选课系统。

系统以「学生选课」为核心场景，覆盖从**课程查询 → 选课 → 容量与冲突校验 → 退课 → 结果查询**的完整业务闭环，并通过软件工程方法完成需求分析、系统设计、编码实现与测试验证，产出配套的需求规格说明书、设计文档与 UML 建模图表。

> 目标不只是「能跑」，而是**过程规范、文档完整、设计可追溯**——文档与图表同代码一样，都是交付物本身。

## 二、核心功能

| 编号 | 功能 | 说明 |
| --- | --- | --- |
| F1 | **课程查询** | 按课程名 / 教师 / 院系 / 时间等条件检索课程，展示课程容量与已选人数 |
| F2 | **选课** | 学生选定课程并提交，系统实时校验容量与时间冲突 |
| F3 | **退课** | 学生退选已选课程，释放名额，回滚占用 |
| F4 | **人数限制** | 课程容量上限控制，满员后不可再选 |
| F5 | **时间冲突检查** | 校验所选课程与已选课程在时间安排上是否冲突 |
| F6 | **选课结果查询** | 查看个人已选课程清单及选课状态 |

> 需求已定稿：扩展范围**仅保留「候补队列与自动补位」「公告通知」两项**；学分统计、先修课校验、选课日志审计、课表导出、课程评价**明确不做**。
> 完整基线见 [`docs/00-需求确认清单.md`](docs/00-需求确认清单.md)。

## 三、技术栈

> 技术栈已随需求定稿确认。

| 层次 | 方案 | 备注 |
| --- | --- | --- |
| 后端 | Node.js + Express | 与本机 Node v22 环境匹配 |
| 数据库 | SQLite（`node-sqlite3-wasm`） | 纯 JS / WASM 实现，**免原生编译** |
| 前端 | 服务端渲染页面 + 原生 HTML / CSS / JS | 三个角色各自的页面 |
| 版本管理 | Git + GitHub | 见「开发规范」 |

**选型硬约束**：本机开发环境为 Windows，**缺少 Visual Studio 原生编译工具链**，`node-gyp` 编译必然失败。因此必须避开依赖原生编译的包（如 `better-sqlite3`），统一采用纯 JS / WASM 方案。

## 四、快速开始

### 环境要求

- Node.js ≥ 20（开发环境为 v22.22.2）
- **无需安装数据库服务**，也**无需任何原生编译工具链**

### 启动步骤

```bash
npm install        # 1. 安装依赖
npm run init-db    # 2. 初始化数据库并写入演示数据（首次必需）
npm start          # 3. 启动服务
```

启动后访问 <http://localhost:3000>。

### 常用命令

| 命令 | 说明 |
| --- | --- |
| `npm start` | 启动服务（默认端口 3000，可用 `PORT` 环境变量覆盖） |
| `npm run init-db` | 初始化数据库并写入演示数据（已有数据则跳过） |
| `npm run reset-db` | 清空并重建数据库 |
| `npm run smoke` | 运行接口冒烟测试（需先启动服务） |
| `npm run stress` | 运行并发与业务规则验证（自带临时数据库，不影响正式数据） |
| `npm run test:conflict` | 运行时间冲突判定单元测试 |

> 数据库文件默认位于 `data/course-selection.sqlite`，可用 `DB_FILE` 环境变量指定其他路径。

### 注意事项

- 本项目为**单进程**应用：服务运行期间请勿同时执行 `npm run init-db`，否则会提示数据库被占用。
- 若因异常退出（例如在写事务中按 Ctrl+C）导致启动报 `database is locked`，程序会在启动时**自动清理残留锁**并给出提示。

## 五、项目结构

```
course-selection-system/
├── src/
│   ├── server.js          # 启动入口（监听端口、优雅退出）
│   ├── app.js             # Express 应用装配（视图、静态资源、会话、路由）
│   ├── config.js          # 全局配置（端口、会话、节次时间表、角色与周次枚举）
│   ├── db/
│   │   ├── index.js       # 数据库访问层（连接、参数规整、事务）
│   │   ├── schema.sql     # 数据库结构
│   │   └── seed.js        # 演示数据初始化
│   ├── middleware/
│   │   └── auth.js        # 登录校验与角色鉴权
│   ├── routes/            # 路由模块（按业务拆分）
│   └── utils/
│       └── password.js    # scrypt 口令派生与校验
├── views/                 # EJS 页面模板
├── public/css/            # 样式表
├── docs/                  # 软件工程文档与 UML 图表
├── test/smoke.sh          # 接口冒烟测试脚本
└── data/                  # SQLite 数据文件（不入库）
```

### 数据表一览

| 表 | 说明 |
| --- | --- |
| `user` | 用户（学生 / 教师 / 管理员），含角色、院系、年级 |
| `semester` | 学期，含选课窗口的开放与截止时间 |
| `course` | 课程（某学期的开课班次），含容量上限与开课状态 |
| `class_time` | 上课时间，含星期、起止节次、单双周与周次区间 |
| `enrollment` | 选课记录，状态含已选 / 候补 / 已退；候补按加入时间先后排序 |
| `announcement` | 公告 |
| `meta` | 元信息（结构版本、初始化时间） |

## 七、开发规范

### 5.1 提交信息规范

采用约定式提交（Conventional Commits）：

| 前缀 | 用途 |
| --- | --- |
| `feat:` | 新功能 |
| `fix:` | 缺陷修复 |
| `docs:` | 文档变更 |
| `refactor:` | 重构（不改变外部行为） |
| `test:` | 测试相关 |
| `chore:` | 构建、依赖、杂项 |

### 5.2 版本规划

| 版本 | 内容 |
| --- | --- |
| `v0.1.0` | 项目骨架、目录结构、基础配置 |
| `v0.2.0` | 六大核心功能实现 |
| `v0.3.0` | 软件工程文档与 UML 图表 |
| `v1.0.0` | 完整交付（功能 + 文档 + 测试） |

### 5.3 协作方式

**每个功能模块完成后即提交并推送**，保持版本迭代可追溯。
