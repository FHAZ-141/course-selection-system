## 一、概述

### 1.1 编写目的

记录测试设计思路、用例与**实际执行结果**，回答三个问题：

1. 需求是否真的实现了（对照 D1 的验收标准）；
2. 边界与并发是否可靠（这是选课系统最容易出事的地方）；
3. 还有哪些没测到（不掩饰缺口）。

### 1.2 测试范围

| 已覆盖 | 未覆盖（见第九节） |
| --- | --- |
| 12 条功能需求的正常路径与主要异常路径 | 浏览器 UI 自动化（无 Selenium/Playwright） |
| 时间冲突判定的全部边界（26 项单元测试） | 行覆盖率统计（未接入覆盖率工具） |
| 并发选课不超卖、候补补位、窗口规则（15 项） | 多进程/多实例部署场景 |
| 三类角色的权限隔离 | 跨时区、超大容量（万级并发） |
| 表单校验与错误提示文案 | 浏览器兼容性矩阵（仅测 Chrome/Edge） |

## 二、测试策略

### 2.1 分层策略

```
        ╱╲        端到端 77 项（HTTP + 页面内容）
       ╱  ╲       —— 慢、真实、覆盖权限与文案
      ╱────╲
     ╱      ╲     集成 15 项（服务层 + 真实事务）
    ╱        ╲    —— 中速，专门验证并发与补位
   ╱──────────╲
  ╱            ╲  单元 26 项（纯函数）
 ╱______________╲ —— 快、边界密集、可反复跑
```

| 层次 | 脚本 | 数量 | 执行时间 | 命令 |
| --- | --- | --- | --- | --- |
| 单元 | `test/conflict-test.js` | 26 | < 1 秒 | `npm run test:conflict` |
| 集成 | `test/stress-test.js` | 15 | 约 5 秒 | `npm run stress` |
| 端到端 | `test/smoke.sh` | 77 | 约 30 秒 | `npm run smoke`（需服务在跑） |
| **合计** | — | **118** | — | — |

### 2.2 为什么这样分层

这个项目的风险分布极不均匀，测试投入也按风险分配：

| 风险点 | 为什么难测 | 采用的手段 |
| --- | --- | --- |
| 时间冲突判定 | 要造单周课、双周课、跨周次区间、首尾相接等组合，**通过页面造数据几乎不可行** | 抽成纯函数 + 26 条单元测试 |
| 并发不超卖 | 必须真实事务与真实并发 | 服务层并发测试 + 临时数据库 |
| 越权访问 | 需要三种角色逐一试 | HTTP 层端到端 |
| 提示文案 | 只在页面出现 | 断言页面内容片段 |

**反例**：如果把冲突判定写在路由里，就只能靠页面点，26 个边界要造 26 组课程数据——这个设计选择直接决定了可测性。

### 2.3 测试数据

| 数据集 | 来源 | 用途 |
| --- | --- | --- |
| 演示数据 | `npm run init-db`（53 用户 / 33 课程 / 37 段排课 / 114 选课 / 3 公告） | 端到端与手工验证 |
| 临时库（并发） | `test/stress-test.js` 自建，独立目录 | 并发测试，**不污染演示数据** |
| 临时库（端到端） | 通过 `DB_FILE` 环境变量指向临时文件 | 冒烟测试可反复执行、结果可复现 |

**为什么不用演示库跑冒烟**：冒烟会新增/删除课程、发布公告、改选课窗口，
每跑一次演示数据就变一次。用 `DB_FILE` 指向临时库，跑完即弃。

| 项 | 值 |
| --- | --- |
| 操作系统 | Windows 10/11（本机开发环境） |
| Node.js | v24.22.0 |

**为什么不用 Jest / Mocha**：本项目断言数不多（118 项），自研脚本可以直接复用
`courseService`、`enrollmentService` 等真实模块，也能直接读数据库校验结果；
引入框架还要处理 ESM/CJS 与临时库生命周期，收益不明显。

### 3.1 PostgreSQL 环境下的补充执行结果（2026-10-22）

迁移到 PostgreSQL 后，同一套用例在两个环境各跑一遍：

| 套件 | SQLite | PostgreSQL（Neon Singapore） |
| --- | --- | --- |
| 单元（时间冲突判定） | 26/26 | 26/26（纯函数，与库无关） |
| 集成（并发与规则） | 15/15 | **15/15，连跑 3 轮** |
| 端到端冒烟 | 77/77（约 40 秒） | 77/77（约 93~211 秒，受跨境 RTT 影响） |

**关键对比**：并发用例「10 人抢容量 3 的课程」

| 阶段 | 选中 | 候补 | 拒绝 | 结论 |
| --- | --- | --- | --- | --- |
| 加行锁前（P2 结束） | **6** | 4 | 0 | ❌ 超卖一倍 |
| 加行锁后（P3 结束） | **3** | 3 | 4 | ✅ 连跑 3 轮稳定 |

> 这组数据说明：把 SQLite 的 `BEGIN IMMEDIATE` 换成 PG 的 `BEGIN` 后，
> "不超卖"这个特性**确实会失效**，必须显式加 `SELECT ... FOR UPDATE`。

## 六、测试与验证过程中发现的问题

以下问题均为本项目**真实发生过**的，按发现阶段分类。修复后均做了回归验证。

| 编号 | 现象 | 根因 | 修复 | 发现阶段 | 回归 |
| --- | --- | --- | --- | --- | --- |
| BUG-01 | 数字参数写入数据库后变成 `NULL`，**且不报错** | 数据库驱动的 API 只接受数组/对象形式的参数，可变参数只绑定第一个 | 数据层统一 `normalizeParams()` 规整参数 | 开发自测 | ✅ 118 项全过 |
| BUG-02 | 启动报 `database is locked`，重启仍然复现 | `prepare()` 之后未 `finalize()`，写语句一直持锁；异常退出还会残留锁目录 | 改用 Database 级 `run/get/all`（内部自动 finalize）；启动时清理残留锁并提示 | 冒烟首跑 | ✅ 连续多次启动正常 |
| BUG-03 | 会话过期后点击「选课」看到裸 JSON `{"error":"未登录"}` | 鉴权中间件对所有非 GET 请求一律返回 401 JSON | 按 `Accept` 判断：表单请求跳登录页，声明 JSON 的才返回 401 | 冒烟第 3 组 | ✅ TC-E-22 |
| BUG-04 | 冒烟断言"张伟有 4 门课"失败 | 期望值凭印象写，实际为 5 门（漏了后加的 CS113） | 以数据库实际查询为准修正期望值 | 冒烟第 6 组 | ✅ TC-E-64 |
| BUG-05 | `docs/` 中功能编号与需求基线冲突 | `README` 用 F1~F6 表示功能，需求清单里 F 组却是「技术栈与交付」 | 功能项统一改用 `§2.1-N`，修正 19 个文件 50 处 | 文档核对 | ✅ 全局检索无残留 |
| BUG-06 | D4 说上课时间 36 段，实际 37 段 | 新增 CS113 后未同步文档 | 修正为 37（CHANGELOG 中 v0.1.0 的 36 属历史记录，保留） | 部署实测 | ✅ 与实际一致 |
| BUG-07 | 导出的 `.svg` 用浏览器打开报 "tag mismatch: br" | 图表工具默认输出 HTML 标签（`<br>` 未闭合），作为 XML 非法 | 关闭 `htmlLabels` 改输出纯文本节点，并对源码做 HTML 转义 | 出图时报错页 | ✅ 10 张 SVG 全部通过校验 |
| BUG-08 | 状态图渲染成深色块，文字几乎不可读 | 使用了复合状态，主题下渲染为深色填充 | 改为简单状态 + 迁移标签 | 看图 | ✅ 重新出图 |
| BUG-09 | 活动图 867×2727，A4 放不下 | 三个判定条件画成串行菱形 | 合并为一个判定节点、移除空集合边界 | 看图 | ✅ 445×1241 |

**统计**：9 个问题，其中 4 个属于功能缺陷（BUG-01~04），3 个属于文档缺陷（BUG-05~06），2 个属于交付物质量问题（BUG-07~08）。

> 说明：本项目没有独立测试人员，上述问题主要靠**自动化脚本 + 人工核对**发现。
> 这恰恰说明自动化测试的价值——BUG-01 这种"静默错误"如果不写断言，
> 手工点页面很难发现。
