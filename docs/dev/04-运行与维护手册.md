# 04 · 运行与维护手册

> 回答：怎么把系统跑起来？有哪些配置？出问题怎么办？

## 一、环境要求

| 项目 | 要求 | 本项目实测环境 |
| --- | --- | --- |
| Node.js | ≥ 20 | v22.22.2 与 **v24.22.0** 均已验证可用 |
| npm | 随 Node 附带 | 10.9.7 / 11.19.1 |
| 数据库 | **无需单独安装** | 使用 SQLite 单文件 |
| 编译工具链 | **无需** | 所有依赖均为纯 JS / WASM |

### 验证环境是否就绪

```bash
node -v    # 应输出 v20 以上
npm -v     # 应输出 10 以上
```

若提示 `'npm' 不是内部或外部命令`，说明 Node.js 未安装或未加入 PATH。
从 <https://nodejs.org/zh-cn> 下载 **LTS 版**安装包图形化安装即可（安装程序会自动配置 PATH）。
安装完成后需**重新打开命令行窗口**，旧窗口不会自动获得新的 PATH。

## 二、安装与启动

```bash
npm install        # 1. 安装依赖（首次必需，约 75 个包）
npm run init-db    # 2. 初始化数据库并写入演示数据（首次必需）
npm start          # 3. 启动服务
```

见到以下输出即启动成功：

```
==============================================
  选课系统已启动
  本机访问：http://localhost:3000
  演示账号：admin / T1001 / 2024010101，密码均为 123456
  按 Ctrl+C 停止服务
==============================================
```

浏览器访问 <http://localhost:3000>。

### 停止服务

在运行服务的窗口中按 `Ctrl + C`，程序会收到 SIGINT 并优雅关闭数据库连接。

## 三、npm 脚本一览

| 命令 | 作用 | 备注 |
| --- | --- | --- |
| `npm start` | 启动服务 | 等价于 `node src/server.js` |
| `npm run init-db` | 初始化库与演示数据 | **幂等**：已有数据时打印提示并跳过，不会覆盖 |
| `npm run reset-db` | 清空并重建库与演示数据 | ⚠️ 会删除全部数据 |
| `npm run smoke` | 接口冒烟测试 | 需服务已启动；共 77 项用例 |

## 四、环境变量

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `PORT` | `3000` | 服务监听端口 |
| `HOST` | `0.0.0.0` | 监听地址 |
| `DB_FILE` | `data/course-selection.sqlite` | 数据库文件路径 |
| `SESSION_SECRET` | 开发用固定值 | 会话签名密钥，**正式部署务必修改** |

### 用法示例

```bash
# 换端口启动（Windows cmd）
set PORT=3001 && npm start

# 指定数据库文件（可用于并行测试，避免与正在运行的服务抢锁）
set DB_FILE=D:\temp\test.sqlite && npm start
```

> PowerShell 语法不同：`$env:PORT=3001; npm start`。

## 五、故障排查

### 5.1 `database is locked`

**现象**：启动时报 `SQLite3Error: database is locked`。

**原因**：`node-sqlite3-wasm` 用「与数据库文件同名的 `.lock` 目录」实现互斥。
以下两种情况会留下残留锁：

1. 进程在写事务中被强杀（例如写数据时按了 `Ctrl + C`）
2. 已有另一个进程正在使用同一个数据库文件

**对策**：

- 本程序**启动时会自动清理残留锁**并打印提示，通常直接重启即可。
- 若清理失败（权限问题），手动删除 `data/course-selection.sqlite.lock` 目录。
- 若确实是另一个进程在跑：**先停掉它**。常见的误操作是"服务还开着就去执行 `npm run init-db`"。

> ⚠️ **本项目是单进程应用**：同一时刻只允许一个进程打开数据库文件。
> 需要跑压测脚本或重新初始化时，请先停掉服务。

### 5.2 端口被占用（`EADDRINUSE`）

```bash
set PORT=3001 && npm start
```

或先查占用进程（Windows）：

```bash
netstat -ano | findstr :3000
taskkill /PID <进程号> /F
```

### 5.3 页面打开很慢 / 每次查询都要等

**先确认是否在本机正常运行**。若在受限环境（如某些沙箱、杀毒软件实时扫描极严格的目录）
下运行，数据库驱动每次语句都要创建/删除一个锁目录，**文件系统调用会被放大**，
单次查询可能从毫秒级退化到数百毫秒。

**对策**：把数据文件换到系统临时目录对比验证：

```bash
set DB_FILE=%TEMP%\cs-test.sqlite && npm run init-db && npm start
```

若速度恢复正常，说明是目录环境的文件系统开销问题，与本项目代码无关。

### 5.4 `npm start` 报错说找不到依赖模块

```bash
npm install
```

### 5.5 登录后立刻被弹回登录页

多为 `SESSION_SECRET` 变化导致旧 Cookie 失效，重新登录即可。

## 六、数据管理

### 重置为演示数据

```bash
npm run reset-db
```

直接复制 `data/course-selection.sqlite` 文件即可（**复制前请先停止服务**）。
恢复时覆盖回原位置。

## 七、部署提示（F3 上线演示）

若要部署到线上演示环境，程序已满足基本要求：

- 监听 `PORT` 环境变量指定的端口，绑定 `0.0.0.0`
- 无需数据库服务，无需构建步骤
- 启动命令：`npm start`

⚠️ 上线前**必须**设置 `SESSION_SECRET`，并注意 SQLite 数据文件所在目录需可写。
