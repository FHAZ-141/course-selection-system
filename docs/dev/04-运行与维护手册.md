## 一、环境要求

| 项目 | 要求 | 本项目实测环境 |
| --- | --- | --- |
| Node.js | **22.x**（`engines` 已锁定） | 本地 v22.22.2，线上 v22.23.4 |
| npm | 随 Node 附带 | 10.9.7 |
| 数据库 | **两种模式**：离线用 SQLite（无需安装）；联网用 PostgreSQL（Neon，需 `DATABASE_URL`） | 生产：Neon PG 18.6；离线：SQLite 单文件 |
| 编译工具链 | **无需** | 5 个依赖均为纯 JS / WASM |

### 验证环境是否就绪

```bash
node -v    # 应输出 v22.x
npm -v     # 应输出 10 以上
```

若提示 `'npm' 不是内部或外部命令`，说明 Node.js 未安装或未加入 PATH。
从 <https://nodejs.org/zh-cn> 下载 **LTS 版**安装包图形化安装即可（安装程序会自动配置 PATH）。
安装完成后需**重新打开命令行窗口**，旧窗口不会自动获得新的 PATH。

## 二、安装与启动

### 一键启动（推荐）

Windows 下双击项目根目录的 `start.bat`，或在命令行执行 `npm run launch`。
启动器 `start.js` 会自动完成四件事：

| 步骤 | 行为 | 失败时 |
| --- | --- | --- |
| 1. 检查依赖 | `node_modules` 不存在则自动 `npm install` | 提示手动执行 `npm install` |
| 2. 检查数据库 | 有 `DATABASE_URL` 时连云端库；否则检查 `data/*.sqlite` 是否存在，缺则跑 `seed.js` | 提示手动执行 `npm run init-db`（离线）/ `init-db:pg`（云端） |
| 3. 启动服务 | 以子进程运行 `src/server.js`（沿用其日志与优雅退出） | 打印错误并提示常见原因 |
| 4. 打开浏览器 | 轮询 `/health` 就绪后调用系统默认浏览器 | 提示手动复制地址 |

**参数与行为约定**：

| 场景 | 行为 |
| --- | --- |
| 端口 3000 被其他程序占用 | 自动向后找可用端口（最多试 10 个），并打印实际地址 |
| 已有本服务在运行 | 直接打开浏览器，**不重复启动**，避免两个进程抢同一个数据库文件 |
| `--no-browser` | 只启动服务，不开浏览器（服务器 / CI 场景） |
| `--skip-install` | 跳过自动装依赖（离线环境，依赖需预先装好） |
| 按 Ctrl+C | 信号转发给子进程，前端与后端一起退出，不留孤儿进程 |

### 手动启动（命令行）

```bash
npm install        # 1. 安装依赖（首次必需，约 89 个包）
npm run init-db    # 2. 初始化数据库并写入演示数据（首次必需；离线模式）
npm start          # 3. 启动服务

# 连云端库（读取 .env 里的 DATABASE_URL）
npm run init-db:pg
npm run start:pg
```

见到以下输出即启动成功：

```
==============================================
  选课系统已启动
  本机访问：http://localhost:3000
  演示账号：admin / T1001 / 2024010101，密码均为 123456
  按 Ctrl+C 停止服务
==============================================
```

浏览器访问 <http://localhost:3000>。

### 停止服务

在运行服务的窗口中按 `Ctrl + C`，程序会收到 SIGINT 并优雅关闭数据库连接。

## 三、npm 脚本一览

| 命令 | 作用 | 备注 |
| --- | --- | --- |
| `npm run launch` | 一键启动（装依赖 + 建库 + 起服务 + 开浏览器） | 等价于双击 `start.bat` |
| `npm start` | 仅启动服务 | 等价于 `node src/server.js` |
| `npm run init-db` | 初始化库与演示数据 | **幂等**：已有数据时打印提示并跳过，不会覆盖 |
| `npm run reset-db` | 清空并重建库与演示数据 | ⚠️ 会删除全部数据 |
| `npm run smoke` | 接口冒烟测试 | 需服务已启动；共 77 项用例 |
| `npm run stress` | 并发与业务规则验证 | 自带临时库；SQLite 15 项 |
| `npm run test:conflict` | 时间冲突判定单元测试 | 26 项，纯函数 |
| `npm run start:pg` | 连云端库启动 | 读取 `.env`（`node --env-file=.env`） |
| `npm run init-db:pg` / `reset-db:pg` | 云端库初始化 / 重置 | 直接影响线上数据，**重置前确认** |
| `npm run start:prod` | 生产启动（幂等 seed + 起服务） | Render 使用；**不可加 `--reset`** |
| `npm run pack:submission` | 生成 `提交材料/` | 改完 `docs/` 后执行 |

## 四、环境变量

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `PORT` | `3000` | 服务监听端口 |
| `HOST` | `0.0.0.0` | 监听地址 |
| `DATABASE_URL` | 空 | **有值即走 PostgreSQL**；为空回退 SQLite |
| `DB_DRIVER` | 自动判断 | 显式指定 `pg` / `sqlite`（回归测试用） |
| `DB_FILE` | `data/course-selection.sqlite` | 仅离线模式使用 |
| `PG_POOL_MAX` | `10` | PostgreSQL 连接池上限 |
| `PG_SSL` | 默认开启 | 本地自建 PG 可设 `false` 关闭 |
| `SESSION_SECRET` | 开发用固定值 | 会话签名密钥，**正式部署务必修改** |
| `RENDER_GIT_COMMIT` | Render 注入 | 只读；`/health` 用它显示部署提交 |

### 用法示例

```bash
# 换端口启动（Windows cmd）
set PORT=3001 && npm start

# 指定数据库文件（可用于并行测试，避免与正在运行的服务抢锁）
set DB_FILE=D:\temp\test.sqlite && npm start
```

> PowerShell 语法不同：`$env:PORT=3001; npm start`。

## 五、故障排查

### 5.1 `database is locked`

**现象**：启动时报 `SQLite3Error: database is locked`。

**原因**：`node-sqlite3-wasm` 用「与数据库文件同名的 `.lock` 目录」实现互斥。
以下两种情况会留下残留锁：

1. 进程在写事务中被强杀（例如写数据时按了 `Ctrl + C`）
2. 已有另一个进程正在使用同一个数据库文件

**对策**：

- 本程序**启动时会自动清理残留锁**并打印提示，通常直接重启即可。
- 若清理失败（权限问题），手动删除 `data/course-selection.sqlite.lock` 目录。
- 若确实是另一个进程在跑：**先停掉它**。常见的误操作是"服务还开着就去执行 `npm run init-db`"。

> ⚠️ **离线（SQLite）模式是单进程应用**：同一时刻只允许一个进程打开数据库文件。
> 需要跑压测脚本或重新初始化时，请先停掉服务。
> **云端（PostgreSQL）模式没有这个限制**，可以同时开多个实例。

### 5.2 端口被占用（`EADDRINUSE`）

```bash
set PORT=3001 && npm start
```

或先查占用进程（Windows）：

```bash
netstat -ano | findstr :3000
taskkill /PID <进程号> /F
```

### 5.3 页面打开很慢 / 每次查询都要等

**先确认是否在本机正常运行**。若在受限环境（如某些沙箱、杀毒软件实时扫描极严格的目录）
下运行，数据库驱动每次语句都要创建/删除一个锁目录，**文件系统调用会被放大**，
单次查询可能从毫秒级退化到数百毫秒。

**现在最常见的原因是跨境网络**（不是文件系统）。PostgreSQL 模式下每次查询都要走网络：

| 场景 | 实测耗时 |
| --- | --- |
| 本地 → Neon（新加坡，经本机代理） | **约 500 ms / 查询**，整页 1~5 秒 |
| Render → Neon（同区域） | **约 2 ms / 查询** |

**对策**：

- **本地日常开发用 `DB_DRIVER=sqlite`**，需要验证"与线上同一份数据"时再切 PG。
- 云端慢的话看 `/health` 的 `dbMs`，它直接反映一次 `SELECT 1` 的往返耗时。
- 若 SQLite 模式下反而慢，再按老办法换到系统临时目录排除文件系统开销问题。

### 5.4 `npm start` 报错说找不到依赖模块

```bash
npm install
```

### 5.5 登录后立刻被弹回登录页

多为 `SESSION_SECRET` 变化导致旧 Cookie 失效，重新登录即可。

## 六、数据管理

### 重置为演示数据

```bash
npm run reset-db       # 离线（SQLite）
npm run reset-db:pg    # 云端（Neon）—— 约 2.5 分钟，会重建线上数据
```

### 备份

| 模式 | 做法 |
| --- | --- |
| 离线（SQLite） | 复制 `data/course-selection.sqlite`（**复制前先停服务**），恢复时覆盖回原位置 |
| 云端（PostgreSQL） | 用 Neon 控制台的 **Backup & Restore**，或 `pg_dump` |

> 线上数据是持久的（2026-10-22 起），所以"删库重来"不再能靠重新部署实现——
> 必须显式执行 `reset-db:pg`。

## 七、部署提示（F3 上线演示）

线上部署已实际运行（Render + Neon），要点：

- 监听平台注入的 `PORT`，绑定 `0.0.0.0`
- 启动命令用 `npm run start:prod`（幂等 seed + 起服务，**不要加 `--reset`**）
- **必须**设置 `SESSION_SECRET` 与 `DATABASE_URL`
- 数据库在 Neon，进程不写本地盘，因此不再需要持久磁盘

完整步骤与排错见 [06-部署指南](06-部署指南.md)。
