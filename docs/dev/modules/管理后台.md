# 模块：管理后台

> 对应需求：**R8 管理员权限**、**B2 选课窗口配置**、课程容量与排课维护、**D7 账号管理**、**D8 管理员代办选课**
> 相关文件：
> - 服务层 `src/services/adminService.js`（课程与窗口）、`src/services/announcementService.js`（公告）
> - 路由层 `src/routes/admin.js`
> - 页面 `views/admin/*.ejs`（概览、课程列表、课程表单、选课窗口、公告、统计）
> - 前端交互 `public/js/admin-course.js`（动态增删上课时间段）
> - 测试 `test/smoke.sh` 第 5 节（21 项）

---

## 一、职责

**负责**：课程的新增 / 编辑 / 删除、上课时间维护、选课窗口配置、公告管理、选课统计、账号维护和管理员代办选课。

**不负责**：公告的读取展示（`announcementService` + `/announcements`）、选课动作本身（`enrollmentService`）、
教师端视图（后续模块）。

## 三、数据流

### 3.1 保存课程（新增 / 编辑共用一条路径）

```
POST /admin/courses/:id
   ├── requireRole('admin')
   ├── parseCourse(req.body)         ← 路由层：整理字段
   │      └── parseClassTimes()      ← 把并列的 ct_* 数组拼成结构化数据
   └── adminService.saveCourse(input)
          ├── validateCourse()       ← 字段校验（代码格式、学分范围、节次范围…）
          ├── 课程代码唯一性检查（编辑时排除自身）
          └── db.transaction
               ├── 新增 → INSERT course
               ├── 编辑 → UPDATE course
               ├── DELETE FROM class_time WHERE course_id = ?
               └── 逐条 INSERT class_time        ← 排课「整体替换」
   → 成功：flash + 重定向 /admin/courses
   → 失败：400 重新渲染表单，保留用户已填内容并显示错误
```

**为什么排课要"整体替换"**：课程的上课时间是一组可增删改的记录，
逐条 diff 需要额外的记录标识；先全删再全插更简单，且放在事务里不会出现半截状态。

### 3.2 保存选课窗口

```
POST /admin/semester
   └── adminService.saveWindow({ semesterId, openAt, closeAt })
          ├── normalizeDateTime()    ← datetime-local（2026-10-16T10:00）→ 2026-10-16 10:00:00
          ├── 校验：两个时间都必填、且 截止 > 开放
          └── UPDATE semester SET select_open_at, select_close_at
```

保存后立即生效：`windowService` 每次请求都实时读学期表，不做缓存，
因此改完窗口回到课程查询就能看到效果（演示"截止后不能选课"正是靠这一点）。

## 四、业务规则

| 规则 | 来源 |
| --- | --- |
| 仅管理员可进入后台 | R8 |
| 管理员可增删改课程（含容量、上课时间） | R8 |
| 管理员可配置选课窗口的开放 / 截止时间 | B2 |
| 管理员可发布、置顶、删除公告 | D5 / R8 |
| 课程代码全局唯一 | 数据结构约束 |
| 课程容量上限参与选课时的余量判定 | §2.1-4 |
| 管理员代办仅绕过选课窗口，不绕过课程状态、重复选课、时间冲突、容量和候补上限 | D8 |
| 管理员退课仍触发候补自动补位 | D8 / R3 |
| 管理员移出候补只改变候补状态，不释放已选名额 | D8 |
| 账号采用 scrypt + 独立随机盐；重置密码更新哈希和盐 | D7 |
| 有课程/选课/公告引用的账号不能删除；禁止删除当前登录管理员 | D7 |
| 有课程或选课记录的教师/学生账号不能修改角色 | D7 |
| **退课与候补补位不受选课窗口影响** | B3 / R3（窗口关闭时仍生效，后台配置不会破坏这一点） |

### 课程字段校验

| 字段 | 规则 | 失败提示 |
| --- | --- | --- |
| 课程代码 | 必填；`字母 + 数字`，如 `CS101`；全局唯一 | 请填写课程代码 / 格式应为「字母 + 数字」/ 已被占用 |
| 课程名称 | 必填，≤ 50 字 | 请填写课程名称 / 不能超过 50 字 |
| 授课教师 | 必填，且必须是 `role='teacher'` 的用户 | 请选择授课教师 / 所选教师不存在 |
| 学分 | 0 < 学分 ≤ 20 | 学分需在 0 ~ 20 之间 |
| 容量 | 整数，0 ~ 500 | 容量需为 0 ~ 500 的整数 |
| 上课时间 | 星期 1~7；起止节次 1~12 且 end ≥ start；周次类型三态；周次区间 1~30 且 end ≥ start | 第 N 段上课时间：… |

### 删除课程的限制

**有生效选课记录（`enrolled` 或 `waiting`）的课程不允许删除**，只能改为「停开」。

原因：`enrollment.course_id` 没有设置级联删除。如果强行删除课程，
学生的选课结果会凭空消失；与其级联删掉学生数据，不如提示管理员改用「停开」。

## 五、边界与异常

| 情况 | 处理 |
| --- | --- |
| 非管理员访问任意 `/admin/**` | 403 |
| 未登录访问 | 302 跳登录 |
| 课程 id 非法 / 不存在 | 404 |
| 课程代码重复 | 400 重新渲染表单，提示"已被占用" |
| 排课为空 | **允许**（可以先建课、后补排课；冲突判定对无排课的课程不会误报） |
| 排课行整行为空 | 解析时跳过，不当作非法数据 |
| 结束节次小于起始节次 | 400，提示第 N 段不合法 |
| 选课窗口填了非法格式 | 400，提示"请填写完整的开放与截止时间" |
| 截止时间早于开放时间 | 400，提示"截止时间必须晚于开放时间" |
| 系统中没有学期 | 概览与窗口页显示提示，引导执行 `npm run init-db` |
| 删除有选课记录的课程 | 拒绝，提示"还有 N 条生效中的选课记录，不能删除；请改为「停开」状态" |
| 公告标题 / 内容为空白 | 400，重新渲染并保留已填内容 |
