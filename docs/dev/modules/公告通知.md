# 模块：公告通知

> 对应需求：**D5 公告通知**
> 相关文件：
> - 服务层 `src/services/announcementService.js`
> - 路由层 `src/routes/announcements.js`（查看）、`src/routes/admin.js`（管理）
> - 页面 `views/announcement_list.ejs`、`views/announcement_detail.ejs`
> - 测试 `test/smoke.sh` 第 6 节

---

## 一、职责

**负责**：公告的读取（列表、详情）与写入（发布、删除、置顶）。

**不负责**：首页"最新公告"卡片的布局（在 `views/home.ejs` 中直接调用本服务的 `list()`）。

---

## 二、对外接口

| 方法 | 路径 | 权限 | 说明 |
| --- | --- | --- | --- |
| GET | `/announcements` | 学生 / 教师 / 管理员 | 公告列表（置顶优先，其余时间倒序，最多 50 条） |
| GET | `/announcements/:id` | 学生 / 教师 / 管理员 | 公告详情；不存在 → 404 |

发布与管理入口在管理后台：`GET/POST /admin/announcements`（见 `管理后台.md`）。

### 服务层函数

| 函数 | 说明 |
| --- | --- |
| `list({ limit })` | 列表，置顶优先；`limit` 上限被夹在 200 以内 |
| `get(id)` | 单条，非正整数或不存在返回 `null` |
| `create({ title, content, pinned, authorId })` | 发布，含字段校验 |
| `remove(id)` | 删除 |
| `togglePinned(id)` | 切换置顶 |

## 三、数据流

```
GET /announcements
   ├── requireLogin（三种角色都放行）
   └── announcementService.list({ limit: 50 })
          └── SELECT ... FROM announcement a JOIN user u ON u.id = a.author_id
              ORDER BY a.pinned DESC, a.created_at DESC, a.id DESC
   → 渲染 announcement_list.ejs
```

排序里带 `a.id DESC` 是必要的兜底：同一秒内发布的两条公告 `created_at` 相同，
只按时间排序结果不稳定。

## 四、业务规则

| 规则 | 来源 |
| --- | --- |
| 三种角色均可查看公告 | D5 |
| 置顶公告排在最前，其余按发布时间倒序 | 设计约定 |
| 仅管理员可发布 / 删除 / 置顶 | R8（在管理后台路由上控制） |

### 字段校验（发布时）

| 字段 | 规则 | 违反时提示 |
| --- | --- | --- |
| 标题 | 必填，≤ 100 字 | 请填写公告标题 / 标题不能超过 100 字 |
| 内容 | 必填，≤ 2000 字 | 请填写公告内容 / 内容不能超过 2000 字 |
| 置顶 | 可选，勾选即置顶 | — |

## 五、边界与异常

| 情况 | 处理 |
| --- | --- |
| 公告 id 非数字 / 不存在 | 404 页面，服务端记 `[warn]` |
| 公告被删除后访问原链接 | 404，提示"公告不存在或已被删除" |
| 没有任何公告 | 列表页显示"暂无公告。" |
| 发布时标题或内容为空白字符 | `.trim()` 后判空，按未填写处理 |
| 请求 `limit` 超过 200 | 夹到 200，防止一次拉爆 |
| 内容含换行 | 详情页用 `white-space: pre-wrap` 保留换行，不解释为 HTML |
| 内容含 HTML 标签 | EJS 的 `<%= %>` 自动转义，不会执行 |
