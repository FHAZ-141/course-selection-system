# 模块：选课与退课

> 对应需求：**F2 选课、F3 退课、F4 人数限制、B2 选课窗口、B4 候补队列**
> 配套规则：**R1 候补 FIFO、R2 候补容量、R3 退课补位、R6 校验顺序、R9 退后重选**
> 相关文件：
> - 服务层 `src/services/enrollmentService.js`、`src/services/conflictService.js`、`src/services/windowService.js`
> - 路由层 `src/routes/enrollments.js`
> - 页面 `views/my_enrollments.ejs`、`views/course_list.ejs`、`views/course_detail.ejs`
> - 测试 `test/smoke.sh` 第 3 节

---

## 一、职责

**负责**：选课提交、退课、人数限制判定、候补入队与自动补位、我的选课结果查询。

**不负责**：

- 课程检索与展示 → 课程查询模块
- 时间冲突的**判定算法** → `conflictService`（本模块调用它）
- 课程容量与选课窗口的**配置** → 管理后台模块

---

## 二、对外接口

| 方法 | 路径 | 权限 | 入参 | 结果 |
| --- | --- | --- | --- | --- |
| GET | `/enrollments/my` | 学生 | — | 我的选课页面（已选 / 候补） |
| POST | `/enrollments` | 学生 | `courseId`、`back`（回跳路径） | 302 回跳 + 提示信息 |
| POST | `/enrollments/:courseId/drop` | 学生 | `back` | 302 回跳 + 提示信息 |
| POST | `/enrollments/:courseId/waitlist/cancel` | 学生 | `back` | 302 回跳 + 提示信息 |

> 选课 / 退课一律用 **POST + 重定向（PRG 模式）**，避免浏览器刷新导致重复提交。

### 服务层函数

| 函数 | 说明 |
| --- | --- |
| `enroll(studentId, courseId)` | 选课主流程，返回统一结果对象 |
| `drop(studentId, courseId)` | 退课并触发候补补位 |
| `cancelWaitlist(studentId, courseId)` | 主动退出候补队列 |
| `listMyEnrollments(studentId)` | 我的选课结果（已选课程、候补队列及位次） |
| `countEnrolled(courseId)` | 已选人数（算余量用） |

### 统一结果对象

服务层不抛业务异常，统一返回：

```js
{ ok: true,  code: 'ENROLLED',  message: '选课成功', data: {...} }
{ ok: false, code: 'CONFLICT',  message: '与已选课程时间冲突', data: { conflicts: [...] } }
```

路由层只判断 `ok`，把 `message` 放进 flash 提示，然后重定向。

## 三、数据流

### 3.1 选课 `POST /enrollments`

```
routes/enrollments.js
   ├── requireLogin + requireRole('student')
   ├── 取 courseId、back（回跳路径经安全校验）
   └── enrollmentService.enroll(req.user.id, courseId)
          │
          └── db.transaction（BEGIN IMMEDIATE — 全程持有写锁）
               ├── ① 课程存在？属于当前学期？
               ├── ② 选课窗口开放？          ← windowService   （B2）
               ├── ③ 课程未停开？
               ├── ④ 是否已选中 / 已在候补？  ← enrollment 表
               ├── ⑤ 与已选课程时间冲突？     ← conflictService （C1~C3 / R4）
               ├── ⑥ 余量是否足够？
               │      ├── 够 → 写 status='enrolled'              （F2）
               │      └── 不够 → 写 status='waiting'             （B4）
               │              + waitlist_joined_at = 当前时间     （R1）
               │              + 检查候补队列是否已达上限          （R2）
               └── ⑦ 返回结果
```

**校验顺序（R6）不可随意调整**：先窗口、再重复、再冲突、最后余量并占用名额。
把这个顺序放在一个事务里，才能保证并发下"余量不超卖"。

### 3.2 退课 `POST /enrollments/:courseId/drop`

```
db.transaction
   ├── ① 该生是否确实处于 enrolled 状态？否则拒绝
   ├── ② 置为 'dropped'，清空 waitlist_joined_at
   │      ⚠️ 退课**不校验选课窗口**（B3）
   └── ③ 触发候补补位 promoteNext(courseId)          （R3）
          ├── 余量是否 > 0？否则结束
          ├── 取候补队列（ORDER BY waitlist_joined_at, id）  （R1）
          ├── 从队首依次向后找：
          │     · 与该生已选课程冲突 → 跳过，保留其队列位置
          │     · 不冲突 → 置为 enrolled，结束
          └── 队列中无人可补 → 名额空着，不做任何操作
```

## 四、业务规则

| 规则 | 来源 |
| --- | --- |
| 选课窗口关闭时禁止选课 | B2 |
| **退课不受选课窗口限制**，任何时间均可退 | B3 |
| 已选人数达到容量上限后不再接受选课 | F4 |
| 满员时可加入候补队列，按加入时间先后排序（FIFO） | B4 / R1 |
| 候补队列人数上限 = 课程容量 | R2 |
| 学生退课后，若候补队列非空且有余量，自动补位队首学生 | B4 / R3 |
| **候补补位不受选课窗口开关影响** | R3 |
| 退课后可重新选同一门课，但须重新排入候补队尾 | R9 |
| 选课与退课必须在单个事务内完成 | R6 / E2 |

### 时间冲突判定（R4）

两门课冲突 ⟺ **星期相同** 且 **节次区间真正重叠** 且 **周次集合有交集**

- 节次重叠判定用闭区间：`a.start ≤ b.end && b.start ≤ a.end`
  → 1-2 节与 3-4 节**不算冲突**（相邻时段不算，C3）
- 周次集合：由「每周/单周/双周 + 起止周」推导，逐周判断奇偶性，
  区间最长 16 周，逐个比对成本可忽略

### 两个已拍板的边界决策

| 决策 | 结论 | 理由 |
| --- | --- | --- |
| 课程已满、要转入候补时，是否仍校验时间冲突 | **仍校验** | 规则统一；否则会出现"排到队首却因冲突选不上"，学生体验更差 |
| 候补补位时队首学生有冲突（他后来选了别的课） | **跳过并顺延给下一位，该生仍保留在队列中** | 不卡住队列；他调整课表后下次仍有机会。若直接移出队列，对因临时冲突的学生过于严厉 |

## 五、边界与异常

| 情况 | 处理 | 结果码 |
| --- | --- | --- |
| 课程 id 不存在或非数字 | 拒绝 | `COURSE_NOT_FOUND` |
| 系统未配置学期 / 未配置选课窗口 | 拒绝，提示"选课窗口未开放" | `WINDOW_CLOSED` |
| 窗口尚未开始 / 已截止 | 拒绝，提示具体状态 | `WINDOW_CLOSED` |
| 课程已停开（`status='closed'`） | 拒绝 | `COURSE_CLOSED` |
| 已经选中该课 | 拒绝，不产生重复行 | `ALREADY_ENROLLED` |
| 已在该课候补队列中 | 拒绝 | `ALREADY_WAITING` |
| 与已选课程时间冲突 | 拒绝，并在提示中列出冲突课程 | `CONFLICT` |
| 候补队列已达上限（= 容量） | 拒绝，提示"候补队列已满" | `WAITLIST_FULL` |
| 退课但并未选中该课 | 拒绝 | `NOT_ENROLLED` |
| 退课后候补队列为空 | 正常退课，无名额补位 | — |
| 退课后候补全员冲突 | 正常退课，**名额空着**，不强制补位 | — |
| 重复提交（双击按钮） | 第一次成功，第二次因 `ALREADY_ENROLLED` 被拒绝 | — |
| 非学生角色访问 | 403（路由层拦截） | — |

### 并发安全说明（重要，写文档时要讲清楚）

本项目是**单进程同步**应用，`node-sqlite3-wasm` 为同步 API，Node 单线程执行，
因此同一进程内的两个选课请求不会交错执行——这是第一道保障。

第二道保障是**数据库事务**：整个"校验 + 占用名额"在一个 `BEGIN IMMEDIATE` 事务内完成，
事务开始时即获取写锁。即使将来部署为多进程/多实例，也不会出现两个请求同时读到
"还剩 1 个名额"然后都写成功的超卖问题。

第三道保障是**容量判定基于实时计数**：`countEnrolled()` 在事务内重新统计，
不依赖页面上看到的旧数字。

## 六、扩展点

| 将来要支持… | 应改哪里 |
| --- | --- |
| 学分上限 | `enroll()` 中新增一步校验（当前需求明确不做） |

#### 7.1 并发不超卖（需求 E2 / E3 的核心验证）

**结论：容量未被突破，不存在超卖。**
