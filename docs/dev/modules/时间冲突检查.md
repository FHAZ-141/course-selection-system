# 模块：时间冲突检查

> 对应需求：**C1 时间粒度、C2 单双周、C3 相邻时段**；配套规则 **R4 冲突判定式**
> 相关文件：
> - `src/services/conflictService.js`（判定逻辑，纯函数为主）
> - `src/services/classTimeService.js`（上课时间读取）
> - `test/conflict-test.js`（单元测试，26 项）
> 被谁使用：选课模块（选课时校验）、教师端（授课冲突提示）

---

## 一、职责

**负责**：判断两门课在时间上是否冲突；找出与某学生已选课程冲突的课程；
找出某教师所授课程之间的冲突。

**不负责**：展示上课时间（那是 `utils/format.js` 的活）、阻止冲突错误数据入库（管理后台的活）。

---

## 二、对外接口

| 函数 | 入参 | 返回 | 用途 |
| --- | --- | --- | --- |
| `timesConflict(a, b)` | 两段上课时间对象 | `boolean` | 判断两段是否冲突 |
| `periodsOverlap(a, b)` | 同上 | `boolean` | 节次区间是否重叠 |
| `weeksOverlap(a, b)` | 同上 | `boolean` | 周次是否有交集（含单双周） |
| `matchWeekType(week, type)` | 周序号、周次类型 | `boolean` | 某周是否属于该类型 |
| `findStudentConflicts(studentId, targetCourseId)` | 学生 id、目标课程 id | 冲突列表（含冲突课程与具体冲突的时间段对） | 选课校验 / 详情页提示 |
| `findTeacherConflicts(teacherId)` | 教师 id | 冲突课程对列表 | 教师端 R7 |

## 三、判定式（R4，核心）

> 两门课冲突 ⟺ **星期相同** 且 **节次区间真正重叠** 且 **周次集合有交集**

```js
timesConflict(a, b)
  = a.day_of_week === b.day_of_week
 && a.start_period <= b.end_period && b.start_period <= a.end_period
 && weeksOverlap(a, b)
```

三个条件**必须同时成立**，缺一不可。任一条不满足就不算冲突。

### 3.1 节次重叠：闭区间，相邻不算

用闭区间比较 `start ≤ end && start ≤ end`。

| 情形 | 结果 | 说明 |
| --- | --- | --- |
| 1-2 与 1-2 | 冲突 | 完全相同 |
| 1-2 与 3-4 | **不冲突** | 相邻时段，中间有课间，**符合需求 C3** |
| 1-2 与 2-3 | 冲突 | 第 2 节重叠 |
| 1-4 与 2-3 | 冲突 | 包含关系 |
| 1-3 与 5-6 | 不冲突 | 完全错开 |

> ⚠️ 这里有一个容易被"顺手优化"掉的点：如果把判定写成
> `a.end_period + 1 >= b.start_period`，就会把 1-2 与 3-4 误判为冲突。
> 那是"必须留出间隔"的另一种规则，**需求方明确选择了不算冲突**。改动前请先看需求清单 C3。

### 3.2 周次交集：由「三态 + 区间」推导

周次不是位图，而是「每周 / 单周 / 双周」+「起始周 ~ 结束周」的组合（R5）。
求交集的做法是：

1. 先取两个周次区间的数值交集 `[max(start), min(end)]`，为空则直接不冲突；
2. 在这个小区间内**逐周**判断是否同时满足两者的单双周类型（最多 16 周，成本可忽略）。

| 情形 | 结果 | 说明 |
| --- | --- | --- |
| 每周 1-16 vs 每周 1-16 | 冲突 | — |
| 单周 1-16 vs 双周 1-16 | **不冲突** | 周次集合完全不相交，**符合需求 C2** |
| 单周 1-16 vs 每周 1-16 | 冲突 | 每周包含单周 |
| 每周 1-8 vs 每周 9-16 | 不冲突 | 周次区间不相交 |
| 单周 1-3 vs 单周 3-5 | 冲突 | 第 3 周重叠 |

## 四、数据流

```
findStudentConflicts(studentId, targetCourseId)
   ├── classTimeService.getByCourseId(targetCourseId)        ← 目标课程的上课时间
   ├── classTimeService.loadStudentEnrolledTimes(studentId)  ← 该生已选课程的全部上课时间
   ├── 两两比对调用 timesConflict（跳过目标课程自身）
   └── 按课程聚合返回：{ course_id, code, name, pairs: [{mine, target}] }
```

`pairs` 里保留了**具体是哪两段撞上了**，便于详情页精确提示"周二 3-4 节与《高等数学 A》冲突"。

---

## 五、边界与异常

| 情况 | 处理 |
| --- | --- |
| 目标课程没有排课（`class_time` 为空） | 直接返回空数组，视为不冲突 |
| 学生没有任何已选课程 | 直接返回空数组 |
| 目标课程已在学生的已选列表中（自查） | 比对时跳过自身，不报冲突 |
| 同一门课有多段上课时间 | 逐段比对，任一段冲突即算冲突 |
| 一门课的多段之间互相冲突 | 本模块不管；属排课数据问题，交管理后台校验 |
| 教师没有任何课程 | `findTeacherConflicts` 返回空数组 |

## 六、扩展点

| 将来要支持… | 应改哪里 |
| --- | --- |
| 跨校区通勤冲突 | 需给 `course` 加校区字段，`timesConflict` 增加"同校区判定"分支（需求 C4 当前明确不做） |
| 更细的周次表达（指定位图） | 改 `weeksOverlap` 为位运算，`class_time` 表需增加位图字段 |

| 教师端排课冲突校验（写入前） | 复用 `findTeacherConflicts`，在管理后台保存课程时调用 |

## 七、验证记录

### 2026-10-16 · v0.2.0 首次实现

**自动化**：`npm run test:conflict` 共 **26 项全部通过**，覆盖：

| 分组 | 用例数 | 关键用例 |
| --- | --- | --- |
| 节次重叠 | 7 | 相邻时段 1-2 与 3-4 不冲突（C3）；首尾相接 1-2 与 2-3 冲突 |
| 星期 | 2 | 不同星期不冲突 |
| 单双周 | 4 | 单周与双周同天同时段不冲突（C2）；单周与每周冲突 |
| 周次区间 | 6 | 区间不相交不冲突；首尾相接 1-8 与 8-16 冲突 |
| 组合判定 | 3 | 三个条件必须同时满足 |
| 辅助函数 | 4 | `periodsOverlap` / `weeksOverlap` 直接断言 |

**为什么单独做纯函数测试**：单双周与相邻时段这两个规则很难通过页面造数据验证，
而 `timesConflict` 不依赖数据库，直接对函数断言最可靠、最快。

**集成验证**：选课模块的冒烟测试中有"与《高等数学 A》时间冲突被拒绝"一项通过，
证明本模块被正确接入选课流程（见 `选课与退课.md`）。
