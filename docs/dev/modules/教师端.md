# 模块：教师端

> 对应需求：**R7 教师权限**、**Q3 授课时间冲突提示**（需求确认清单第四节）
> 相关文件：
> - 服务层 `src/services/teacherService.js`（复用 `conflictService`、`classTimeService`）
> - 路由层 `src/routes/teacher.js`
> - 页面 `views/teacher/home.ejs`、`course_list.ejs`、`course_students.ejs`、`conflicts.ejs`
> - 测试 `test/smoke.sh` 第 6 节（11 项）

---

## 一、职责

**负责**：教师查看自己所授课程、某门课的选课名单与候补队列、自己所授课程之间的时间冲突。

**不负责**：修改课程（管理后台）、选课退课（学生端）、时间冲突的判定算法（`conflictService`）。

---

## 二、对外接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/teacher` | 教师端首页：课程数、选课人次、候补人次、冲突提示 |
| GET | `/teacher/courses` | 我所授课程列表（含容量、已选、候补、排课） |
| GET | `/teacher/courses/:id/students` | 某门课的已选名单 + 候补队列 |
| GET | `/teacher/conflicts` | 授课时间冲突详情 |

**权限**：整个模块挂 `requireLogin, requireRole('teacher')`，学生与管理员访问 403。

### 服务层函数

| 函数 | 说明 |
| --- | --- |
| `overview(teacherId)` | 概览数字（含冲突处数） |
| `listMyCourses(teacherId)` | 所授课程列表，附上课时间 |
| `getCourseStudents(teacherId, courseId)` | 课程 + 已选名单 + 候补队列；**不属于本人时返回 null** |
| `findMyConflicts(teacherId)` | 转调 `conflictService.findTeacherConflicts` |

## 三、权限边界的实现方式（重要）

`getCourseStudents` 把 `teacher_id` 直接写进 WHERE 条件：

```js
SELECT c.* FROM course c
 WHERE c.id = ? AND c.teacher_id = ?
```

而不是"先按 id 查出来、再在 JS 里比对 `course.teacher_id === teacherId`"。

**为什么**：前者漏写条件的后果是"查不到"（安全的方向）；后者漏写比对的后果是"越权能看"（危险的方向）。
路由层再区分两种情况给出**不同的状态码**：

```js
if (!data) {
  if (课程根本不存在) → 404
  else                → 403 你只能查看自己所授课程的选课名单
}
```

区分 404 与 403 是为了让问题可诊断：403 说明"课存在但不是你的"，404 说明"课不存在"。

## 四、数据流

```
GET /teacher/courses/:id/students
   ├── requireRole('teacher')
   ├── teacherService.getCourseStudents(req.user.id, req.params.id)
   │      ├── 按 (id, teacher_id) 查课程 → 不属于本人则 null
   │      ├── 查该课的选课与候补记录（联表 user 取学号姓名）
   │      └── 已选在前、候补在后；候补内部按 waitlist_joined_at 排序
   └── 渲染 course_students.ejs
```

冲突页则直接复用 `conflictService.findTeacherConflicts(teacherId)`：
它把该教师所有在开课程的排课取出来两两比对，返回冲突的课程对与**具体撞上的时间段**，
页面把时间段展示成左右对照，方便教师判断该调哪一门。

## 五、业务规则

| 规则 | 来源 |
| --- | --- |
| 教师只能查看**自己所授**课程的选课名单 | R7 |
| 教师端展示已选人数与候补队列（候补按位次） | R7 + B4 |
| 教师可查看自己所授课程之间的时间冲突 | Q3 |
| 冲突判定口径：星期相同 + 节次真正重叠 + 周次有交集 | R4 / C1~C3 |
| 教师不可修改课程、不可替学生选退课 | R7 |

### 关于演示数据

种子数据里**故意**安排了一处冲突：张伟（T1001）的《程序设计基础》（CS101）
与《计算机图形学》（CS113）都排在**周一第 1-2 节**。

真实教务系统里这正是需要被发现的排课事故，加这条数据的目的是让"授课冲突提示"
这个功能在演示时**不是一片空白**，可以直接看到效果。

## 六、边界与异常

| 情况 | 处理 |
| --- | --- |
| 学生 / 管理员访问 `/teacher/**` | 403 |
| 未登录访问 | 302 跳登录 |
| 查看他人课程名单 | 403，提示"你只能查看自己所授课程的选课名单" |
| 查看不存在的课程名单 | 404 |
| 教师名下没有课程 | 首页与列表显示"暂无排课" |
| 课程没有排课时间 | 列表显示"未排课"，冲突判定不会误报 |
| 课程没有学生选中 | 名单显示"还没有学生选中这门课" |
| 没有候补 | 显示"当前没有学生候补" |
| 所授课程之间无冲突 | 显示"无冲突"并说明判定口径 |
