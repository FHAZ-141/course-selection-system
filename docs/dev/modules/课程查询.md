> 对应需求：**§2.1-1 课程查询**
> 相关文件：
> - 服务层 `src/services/courseService.js`
> - 路由层 `src/routes/courses.js`

> - 页面 `views/course_list.ejs`、`views/course_detail.ejs`

---

## 一、职责

**负责**：按条件检索课程、汇总每门课的容量与选课情况、展示课程详情。

**不负责**：

- 选课 / 退课动作 → 见 `选课与退课` 模块
- 时间冲突判定 → 见 `时间冲突检查` 模块（本模块只负责**展示**上课时间，不判断冲突）
- 教师端与管理端的课程编辑 → 见 `管理后台` 模块

## 二、对外接口

| 方法 | 路径 | 权限 | 入参 | 返回 |

## 三、数据流

```
GET /courses?keyword=数据结构&dayOfWeek=1
        │
routes/courses.js
        ├── requireLogin + requireRole('student','teacher','admin')
        ├── 从 req.query 取检索条件（统一转成字符串并 trim）
        ├── 若当前用户是学生 → 传 studentId，否则传 null
        └── courseService.listCourses({...})
                │
        courseService
                ├── 1. 取当前学期（无学期直接返回空结果）
                ├── 2. 拼 WHERE 条件查询 course 主表
                │      · 每个条件只在需要时才追加，参数按注入顺序排列
                │      · 已选/候补人数用两个相关子查询统计，避免 N+1
                ├── 3. 批量取这些课的 class_time，按 course_id 分组
                ├── 4. 批量取"我"对这些课的 enrollment 状态
                └── 5. decorate()：在内存中合并，计算派生字段
                       remaining / isFull / selectable / reason / my_status
        │
views/course_list.ejs 渲染表格 → 浏览器
```

**为什么上课时间和"我的状态"不做进主 SQL**：
本项目使用的 SQLite 驱动对占位符顺序敏感，若把子查询混进 `SELECT` 子句，参数顺序会变得难以维护，
一旦写错就会**静默绑定到错误位置**。拆成三条简单查询再在内存中合并，SQL 更简单、更不易出错。
演示级数据量（数十门课）下合并成本可忽略。

## 四、业务规则

| 规则 | 来源 |
| --- | --- |
| 剩余名额 = 容量 − 已选人数，且不小于 0 | §2.1-4 人数限制 |
| 课程状态为 `closed`（停开）时不可选，原因提示"课程已停开" | 种子数据中 CS112 演示此状态 |
| 已选人数 ≥ 容量时标记为满员，原因提示"名额已满，可选候补" | §2.1-4 + B4 候补 |
| 上课时间按"星期 + 节次"展示，并附带上下午时间与周次信息 | C1 时间粒度、C2 单双周 |
| 学生查看时额外标记"我的选课状态"（已选 / 候补中 / 已退） | §2.1-6 选课结果查询 |
| 检索支持课程名或课程代码模糊匹配 | §2.1-1 课程查询 |
| 课程列表只展示**当前学期**的课程 | 需求 A1~A3 学期维度 |

### 派生字段说明

`decorate()` 为每门课程补充以下字段，供模板直接使用：

| 字段 | 含义 |
| --- | --- |
| `enrolled_count` | 已选人数（`status='enrolled'`） |
| `waitlist_count` | 候补人数（`status='waiting'`） |
| `remaining` | 剩余名额 |
| `isFull` | 是否已满 |
| `selectable` | 当前是否可被选课（停开或满员时为 false） |
| `reason` | 不可选的原因文案 |
| `class_times` | 该课的全部上课时间 |
| `my_status` | 当前学生对该课的状态，非学生或未选为 `null` |

## 五、边界与异常

| 情况 | 处理方式 |
| --- | --- |
| 未登录访问 | 302 跳 `/login?next=/courses`，登录后跳回 |
| 角色不符 | 本模块三种角色都放行，不涉及 |
| 课程 id 不是数字 / 不存在 | 404 页面，提示"课程不存在：xxx"，服务端记 `[warn]` |
| 系统中没有当前学期 | 列表页展示"尚未配置学期"，课程数为 0，不报错 |
| 课程未排课 | 上课时间列显示"未排课"，详情页显示提示 |
| 容量为 0 | 进度条按 100% 显示并标红，始终视为满员 |
| 检索条件为空白字符串 | 视为未提供该条件（`.trim()` 后判空） |
| 检索无结果 | 显示空态提示"没有符合条件的课程，换个条件试试。" |
| 筛选参数非法（如 `dayOfWeek=abc`） | 生成 SQL 时按普通值处理，查不到结果即返回空列表，不抛异常 |

## 六、扩展点

| 将来要支持… | 应改哪里 |
| --- | --- |
| 增加筛选维度（如按学分、按时间区间） | `courseService.listCourses` 的 WHERE 拼装处 + `course_list.ejs` 的筛选栏 |
| 课程分页 | `listCourses` 增加 `limit/offset`，返回 `total`；列表页加分页控件 |
| 同课多班次 | 需先改数据结构（见 `02-数据库设计说明` 的扩展点），本模块查询随之调整 |
| 展示"是否与已选课程冲突" | 复用 `conflictService`，在 `decorate()` 中为每门课追加 `conflict` 字段 |
| 教师端复用列表 | 复用 `listCourses({ teacherId })`，另建教师视角的模板 |
