## 二、权限矩阵

| 路径前缀 | 学生 | 教师 | 管理员 | 未登录 |
| --- | --- | --- | --- | --- |
| `/health`、`/login` | 公开 | 公开 | 公开 | 公开 |
| `/`（首页） | ✅ | ✅ | ✅ | → 跳登录 |
| `/courses/**` | ✅ | ✅ | ✅ | → 跳登录 |
| `/enrollments/**` | ✅ | ❌ 403 | ❌ 403 | → 跳登录 |
| `/announcements/**` | ✅ | ✅ | ✅ | → 跳登录 |
| `/teacher/**` | ❌ 403 | ✅ | ❌ 403 | → 跳登录 |
| `/admin/**` | ❌ 403 | ❌ 403 | ✅ | → 跳登录 |

### 实现方式

- 登录校验：`requireLogin`
- 角色校验：`requireRole('student')` / `requireRole('admin')` 等，见 `src/middleware/auth.js`
- **每个路由模块在文件顶部统一挂载**，不要逐个路由单独判断，避免漏加：

  ```js
  router.use(requireLogin, requireRole('admin'));
  ```

> ⚠️ **加新路由时的必做检查**：问自己"这个页面哪些角色能访问？"，
> 然后确保 `router.use(...)` 里挂上了对应的 `requireRole`。
> 漏挂 = 越权漏洞，冒烟测试里有专门的越权用例（学生访问 `/teacher` 应得 403）。

## 三、响应约定

### 3.1 页面请求（返回 HTML）

| 场景 | 做法 |
| --- | --- |
| 成功 | 重定向到目标页（`res.redirect`），避免刷新重复提交 |
| 参数校验失败 | 重新渲染当前页，带上 `error` 变量显示提示，**保留用户已填内容** |
| 未登录（表单请求） | 302 跳 `/login?next=<原路径>`；非 GET 请求跳回首页（无法重放） |
| 无权限 | 403 渲染 `views/error.ejs` |
| 找不到 | 404 渲染 `views/error.ejs` |
| 服务器错误 | 500 渲染 `views/error.ejs`，同时打印完整堆栈到控制台 |

> 4xx 属于正常的客户端错误，只打印一行 `[warn]`；5xx 才打印完整堆栈 `[error]`，
> 便于在日志里快速区分"用户走错路"和"程序出问题"。

### 3.2 脚本 / 接口请求（返回 JSON）

用于并发压测脚本等场景，约定统一格式：

```json
{ "ok": true, "data": { } }
{ "ok": false, "message": "课程已满" }
```

未登录时，**只有声明了 `Accept: application/json`（或 `X-Requested-With: XMLHttpRequest`）
的请求**才返回 HTTP 401 + `{"ok":false,"message":"请先登录"}`；
普通表单提交一律重定向到登录页，避免用户看到裸 JSON。

## 四、命名规范

| 对象 | 规则 | 示例 |
| --- | --- | --- |
| 数据库表 / 字段 | 小写 + 下划线 | `class_time`、`day_of_week` |
| JS 变量 / 函数 | 小驼峰 | `courseId`、`findConflicts()` |
| 路由文件 | 复数名词 | `courses.js`、`enrollments.js` |
| 服务文件 | 单数 + Service | `enrollmentService.js` |
| 视图文件 | 小写 + 下划线 | `course_list.ejs` |
| URL 路径 | 小写 + 连字符，资源用复数 | `/admin/courses/new` |
| CSS 类名 | 小写 + 连字符 | `.stat-card` |
| 常量 | 大写下划线 | `DEMO_PASSWORD` |

## 五、视图渲染约定

所有页面模板必须遵循同一结构，保证导航栏与页脚一致：

```ejs
<%- include('partials/header') %>

<!-- 页面内容 -->

<%- include('partials/footer') %>
```

`res.locals` 中可用的公共变量（由 `middleware/auth.js` 注入）：

| 变量 | 说明 |
| --- | --- |
| `currentUser` | 当前登录用户对象，未登录为 `null` |
| `roles` | 角色枚举：`{ student: '学生', ... }` |
| `weekTypes` | 周次枚举：`{ all: '每周', odd: '单周', even: '双周' }` |
| `periods` | 节次与时间的映射表 |
| `activePath` | 当前路径，用于导航高亮 |
| `appName` / `appVersion` | 应用名与版本号（`app.js` 中注入） |

## 六、操作回执（Flash）约定

选课、退课这类写操作用 **POST + 重定向（PRG）**，结果提示通过 session 里的 flash 传递。
**统一走 `src/utils/flash.js`**，路由层不要自己拼 `req.session.flash = {...}`。

### 6.1 三种结果与对应文案

| 结果 | 页面表现 | 示例 |
| --- | --- | --- |
| 成功且**写入了数据库** | 绿色条 + 第二行「已写入 云端数据库 PostgreSQL · 时间」 | `选课成功：编译原理 已写入 云端数据库 PostgreSQL · 2026-10-22 10:19:58` |
| 成功但**未写库**（如登录） | 绿色条，**不带**「已写入」 | `已登录：谢文轩（学生）` |
| 业务拒绝 | 红色条 + 第二行「本次操作未生效（错误码）」 | `你已经选中了「编译原理」 本次操作未生效（ALREADY_ENROLLED）` |

> 为什么要区分"是否写库"：数据库在云端，用户会关心"存上去了没有"。
> 只对真正落库的操作显示「已写入 <库>」，避免登录这种只读操作也声称写库。

### 6.2 用法

```js
const { setFlash, flashAndBack } = require('../utils/flash');

// 业务结果 { ok, code, message } → 提示并回跳（选课/退课/删改，都会落库）
flashAndBack(req, res, result, '/courses');

// 未落库的操作（如登录）传 persisted:false
setFlash(req, { ok: true, message: `已登录：${user.name}`, persisted: false });

// 自定义失败
setFlash(req, { ok: false, message: '系统未配置学期', detail: 'SEMESTER_NOT_CONFIGURED' });
```

flash 对象结构：

```js
{
  type: 'ok' | 'error',
  message: '提示文案',            // 给人看的中文
  detail: 'CODE' | null,         // 失败时的错误码
  target: '云端数据库 PostgreSQL' | null,  // 落库位置（仅"成功且写库"）
  at: '2026-10-22 10:19:58' | null
}
```

### 6.3 模板渲染契约（改模板时必须知道）

`views/partials/header.ejs` 中：

```html
<div class="alert alert-xxx">文案<span class="alert-meta">回执</span></div>
```

**文案必须紧跟在 `class="alert alert-xxx">` 之后，中间不能插入任何标签。**
两个测试脚本用正则 `alert alert-(ok|error)">[^<]*` 提取文案，
一旦中间出现标签，全部涉及提示的用例会取到空字符串（本次踩过一次）。
