# 部署指南（Render 免费版）

> 对应需求：**F3 上线演示**——除本地运行外，另生成在线可访问链接。
> 本文记录线上部署的完整步骤、限制与排错方法。

---

## 一、为什么选 Render

| 候选 | 判断 |
| --- | --- |
| **Render（采用）** | 免费、**不需要信用卡**、连 GitHub 自动部署、固定 HTTPS 地址、依赖 `engines` 自动装 Node |
| Railway | 免费额度只剩 $1/月，跑常驻服务不够；Hobby 需 $5/月 |
| Fly.io | 免费额度尚可，但**必须写 Dockerfile**，与需求 F2「不做 Docker 部署」冲突 |
| Vercel / Netlify | 是 serverless 模型，函数超时 10 秒，跑不了常驻 Express + 本地 SQLite |
| 国内云托管 | 访问快，但需实名、配置繁琐，且免费额度规则常变 |

Render 的免费 Web Service 满足"链接发出去，对方随时能点开"，
且不引入 Docker，与项目既有约束一致。

## 二、应用对平台的要求（已全部满足）

| 要求 | 现状 |
| --- | --- |
| 常驻 HTTP 进程 | Express，`server.js` 自己 `listen` |
| 端口由平台指定 | `src/config.js` 读 `PORT` 环境变量 |
| 监听 `0.0.0.0` | `host` 默认 `0.0.0.0`，`render.yaml` 里再次显式声明 |
| Node 版本 | `engines: { node: "22.x" }`（线上实测 v22.23.4） |
| 无原生编译依赖 | 5 个运行时依赖（express / express-session / ejs / node-sqlite3-wasm / pg）全是纯 JS |
| 可写文件系统 | **不再需要**：数据库在 Neon，进程不写本地盘（离线模式才用 `data/`） |
| 优雅退出 | `server.js` 监听 `SIGTERM`，关闭连接后再关库 |
| 健康检查端点 | `GET /health`，与启动器共用 |

## 三、为部署做的三处适配

### 3.1 `start:prod` 脚本（**当前不带 `--reset`**）

```json
"start:prod": "node src/db/seed.js && node src/server.js"
```

**为什么先 seed**：首次部署时云端库是空的，需要建表 + 写入演示数据。
`seed.js` 本身是幂等的——检测到已有用户就跳过。

**为什么不能带 `--reset`**（2026-10-22 迁移后修订）：

| 做法 | 后果 |
| --- | --- |
| `seed.js`（幂等，采用） | 首次部署建库；之后重启保留全部数据 |
| `seed.js --reset`（**禁止**） | 每次部署**清空线上数据**；且 PG 全量重建约 155 秒，有健康检查超时风险 |

> 迁移前用 `--reset` 是对的：那时数据在容器本地盘，重启即丢，清库反而能保证「代码与数据同版本」。
> 迁移后数据在 Neon，`--reset` 的语义从「重置本地临时库」变成「删线上生产数据」——
> 这是本轮最容易踩错的一处，已在 HANDOFF 的「会咬人的坑」里单列一条。

需要重置演示数据时，手动执行 `npm run reset-db:pg`（本地，指向同一个云端库）。

### 3.2 新增 `render.yaml`

把部署配置写进仓库，避免"在控制台点了一堆，过两个月忘了怎么点的"。

```yaml
services:
  - type: web
    name: course-selection-system
    runtime: node          # 不用 Docker（F2）
    plan: free
    region: singapore      # 离国内最近的节点
    branch: main
    buildCommand: npm install
    startCommand: npm run start:prod
    healthCheckPath: /health
    autoDeploy: true
    envVars:
      - key: NODE_ENV
        value: production
      - key: HOST
        value: 0.0.0.0
      - key: SESSION_SECRET
        generateValue: true   # Render 自动生成随机密钥
      - key: DATABASE_URL
        sync: false           # 键在蓝图里、值只在控制台填（不进仓库）
```

**注意**：不显式指定 `NODE_VERSION`，让 Render 按 `engines: 22.x` 选版本。
曾因 `engines` 写成开放区间 `>=20` 而被装成 Node 26，与本地 22 跨 4 个大版本，已收紧为 `22.x`。

**`sync: false` 的作用**：声明「键属于蓝图、但值只在控制台维护」。
若蓝图里完全不写这个键，蓝图同步时可能把控制台加的变量当作多余项清理，
线上会**静默回退到 SQLite**——页面照常，只是数据又变成各自一份。

### 3.3 环境变量

| 变量 | 来源 | 作用 |
| --- | --- | --- |
| `PORT` | **平台自动注入**，不要手动设 | 监听端口 |
| `HOST` | `render.yaml` | 绑定 `0.0.0.0` |
| `NODE_ENV` | `render.yaml` | 生产模式 |
| `SESSION_SECRET` | Render 自动生成 | 会话签名密钥（本地默认值绝不能用于线上） |
| `DATABASE_URL` | **控制台手动填**（`sync: false`） | Neon 连接串；有值即走 PostgreSQL |
| `DB_DRIVER` | 不设置 | 留空则按 `DATABASE_URL` 自动判断 |
| `DB_FILE` | 不设置 | 仅在离线模式下有意义 |

## 四、部署步骤

### 方式一：Blueprint（推荐，配置即代码）

1. 注册 <https://render.com>，用 **GitHub 账号登录**（一键授权即可，不需要信用卡）
2. 控制台右上 → **New** → **Blueprint**
3. 选择仓库 `FHAZ-141/course-selection-system`
4. Render 自动读到 `render.yaml`，显示要创建的服务 → 点 **Apply**
5. 首次构建约 2~5 分钟（装 5 个依赖 + 启动）
6. 完成后得到地址：`https://course-selection-system-xxxx.onrender.com`

### 方式二：手动创建（不读 render.yaml）

1. **New** → **Web Service** → 连接仓库
2. 填写：

| 字段 | 值 |
| --- | --- |
| Language | Node |
| Branch | `main` |
| Build Command | `npm install` |
| Start Command | `npm run start:prod` |
| Instance Type | **Free** |
| Region | Singapore |
| Health Check Path | `/health` |

3. **Environment** 里加 `HOST=0.0.0.0`、`SESSION_SECRET`（点 Generate）、`NODE_ENV=production`
4. Create Web Service

## 五、免费版的三个限制（必须知道）

### 5.1 15 分钟无访问会休眠

| 现象 | 说明 |
| --- | --- |
| 15 分钟没有请求 | 服务自动休眠，不消耗免费时长 |
| 再次访问 | 冷启动 **30~60 秒**，期间浏览器显示 Render 的加载页 |
| 影响 | 答辩前先自己点一次"预热"，避免当众等待 |

每月 750 小时免费时长，单实例够用（休眠不计数）。

### 5.2 数据是持久的（2026-10-22 起）

数据库已迁到 **Neon PostgreSQL**，与 Render 实例的生命周期解耦：

| 事件 | 之前（SQLite 在容器本地盘） | 现在（Neon） |
| --- | --- | --- |
| 服务休眠 / 重启 | 本地文件丢失，重新 seed | **数据保留** |
| 重新部署 | 视平台清理时机，行为不可靠 | **数据保留**（`start:prod` 幂等跳过 seed） |
| 想把演示数据恢复初始 | 重新部署即可 | 手动 `npm run reset-db:pg` |

**代价与应对**：演示过程中产生的选课/公告会累积下来。
演示前如需干净数据，在本地执行一次 `npm run reset-db:pg`（约 2.5 分钟）。

> 这也意味着**不能再用部署来重置数据**——如果哪天发现线上数据"不对"，
> 先确认是不是上一轮演示留下的，而不是怀疑代码。

### 5.3 跨境访问偏慢

节点在新加坡，国内访问比本地慢，冷启动时更明显。
如果只是发给老师"点开看看"，可以接受；现场演示请用内网穿透做备份。

## 六、排错

| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| 构建失败 `Cannot find module` | 依赖没装全 | 看 Build Logs；确认 `package.json` 没被改坏 |
| 启动后 502 / 服务反复重启 | 启动命令报错（如端口没读环境变量） | 看 Logs；确认 `Start Command` 是 `npm run start:prod` |
| 打开首页 500 | 数据库没建成 | 看 Logs 里 `seed.js` 是否报错；确认 `data/` 可写 |
| 登录后立刻掉登录态 | 多实例 + 内存 session | 免费版单实例不会遇到；扩到多实例需改 session 存储 |
| 首次访问等很久 | 正常：冷启动 30~60 秒 | 提前预热 |

**看日志**：Render 控制台 → 服务 → **Logs**，`[warn]` 是用户走错路，`[error]` 才是故障。

## 七、本地与线上的一致性

| 项 | 本地 | Render |
| --- | --- | --- |
| 启动命令 | `npm start` / 双击 `start.bat` / `npm run start:pg` | `npm run start:prod`（幂等 seed，**不带 `--reset`**） |
| 数据库 | 有 `.env` 则连 Neon，无则用 `data/*.sqlite` | **同一个 Neon 库**（通过 `DATABASE_URL`） |
| 数据持久性 | 两种模式都持久 | 持久 |
| 端口 | 3000 或自动顺延 | 平台注入 |
| 会话密钥 | 开发默认值 | 随机生成 |

**本地与线上现在是同一个库**：本地选课，线上教师名单立刻可见；反之亦然（已实测）。
`npm run smoke` 的 77 项断言在 SQLite 与 PostgreSQL 两种模式下都成立。

### 首次部署时的两个坑

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 仓库列表显示 "No repositories found" | 账号是**邮箱注册**，Render 未拿到 GitHub OAuth 授权；仅在 GitHub 上安装 App 不够 | 点「Configure account」完成 OAuth 后，刷新页面才出现仓库列表 |
| GitHub App 安装后列表仍是空 | Render 侧缓存了"未授权"的状态 | 重新进入 `/select-repo?type=blueprint` 即恢复 |

**经验**：Render 的「安装 GitHub App」和「账号 OAuth 授权」是两件事，
只做前者，仓库列表仍然为空。
