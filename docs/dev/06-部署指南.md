# 部署指南（Render 免费版）

> 对应需求：**F3 上线演示**——除本地运行外，另生成在线可访问链接。
> 本文记录线上部署的完整步骤、限制与排错方法。

---

## 一、为什么选 Render

| 候选 | 判断 |
| --- | --- |
| **Render（采用）** | 免费、**不需要信用卡**、连 GitHub 自动部署、固定 HTTPS 地址、依赖 `engines` 自动装 Node |
| Railway | 免费额度只剩 $1/月，跑常驻服务不够；Hobby 需 $5/月 |
| Fly.io | 免费额度尚可，但**必须写 Dockerfile**，与需求 F2「不做 Docker 部署」冲突 |
| Vercel / Netlify | 是 serverless 模型，函数超时 10 秒，跑不了常驻 Express + 本地 SQLite |
| 国内云托管 | 访问快，但需实名、配置繁琐，且免费额度规则常变 |

Render 的免费 Web Service 满足"链接发出去，对方随时能点开"，
且不引入 Docker，与项目既有约束一致。

## 二、应用对平台的要求（已全部满足）

| 要求 | 现状 |
| --- | --- |
| 常驻 HTTP 进程 | Express，`server.js` 自己 `listen` |
| 端口由平台指定 | `src/config.js` 读 `PORT` 环境变量 |
| 监听 `0.0.0.0` | `host` 默认 `0.0.0.0`，`render.yaml` 里再次显式声明 |
| Node 版本 | `package.json` 的 `engines: { node: ">=20" }` |
| 无原生编译依赖 | 4 个运行时依赖（express / express-session / ejs / node-sqlite3-wasm）全是纯 JS |
| 可写文件系统 | SQLite 写到 `data/`，平台提供可写目录（免费版是临时的） |
| 优雅退出 | `server.js` 监听 `SIGTERM`，关闭连接后再关库 |
| 健康检查端点 | `GET /health`，与启动器共用 |

## 三、为部署做的三处适配

### 3.1 新增 `start:prod` 脚本

平台的容器是全新的：仓库里没有 `data/`（已 gitignore），数据库不存在。
所以启动命令不能只跑 `npm start`，要先确保库存在。

```json
"start:prod": "node src/db/seed.js && node src/server.js"
```

`seed.js` 是**幂等**的：库已有数据就打印"跳过写入"并退出 0，不会重复插入。

> 实测：全新路径下执行该命令 → 自动建库 108 KB → **2 秒**就绪 → 冒烟 77 项全过；
> 重复执行不会变成 66 门课，仍是 33 门。

### 3.2 新增 `render.yaml`

把部署配置写进仓库，避免"在控制台点了一堆，过两个月忘了怎么点的"。

```yaml
services:
  - type: web
    name: course-selection-system
    runtime: node          # 不用 Docker（F2）
    plan: free
    region: singapore      # 离国内最近的节点
    branch: main
    buildCommand: npm install
    startCommand: npm run start:prod
    healthCheckPath: /health
    autoDeploy: true
    envVars:
      - key: NODE_ENV
        value: production
      - key: HOST
        value: 0.0.0.0
      - key: SESSION_SECRET
        generateValue: true   # Render 自动生成随机密钥
```

**注意**：不显式指定 `NODE_VERSION`，让 Render 按 `engines` 选 ≥20 的版本。
本项目在 Node 22 与 24 下均实测通过。

### 3.3 环境变量

| 变量 | 来源 | 作用 |
| --- | --- | --- |
| `PORT` | **平台自动注入**，不要手动设 | 监听端口 |
| `HOST` | `render.yaml` | 绑定 `0.0.0.0` |
| `NODE_ENV` | `render.yaml` | 生产模式 |
| `SESSION_SECRET` | Render 自动生成 | 会话签名密钥（本地默认值绝不能用于线上） |
| `DB_FILE` | 不设置 | 用默认 `data/course-selection.sqlite` |

## 四、部署步骤

### 方式一：Blueprint（推荐，配置即代码）

1. 注册 <https://render.com>，用 **GitHub 账号登录**（一键授权即可，不需要信用卡）
2. 控制台右上 → **New** → **Blueprint**
3. 选择仓库 `FHAZ-141/course-selection-system`
4. Render 自动读到 `render.yaml`，显示要创建的服务 → 点 **Apply**
5. 首次构建约 2~5 分钟（装 4 个依赖 + 启动）
6. 完成后得到地址：`https://course-selection-system-xxxx.onrender.com`

### 方式二：手动创建（不读 render.yaml）

1. **New** → **Web Service** → 连接仓库
2. 填写：

| 字段 | 值 |
| --- | --- |
| Language | Node |
| Branch | `main` |
| Build Command | `npm install` |
| Start Command | `npm run start:prod` |
| Instance Type | **Free** |
| Region | Singapore |
| Health Check Path | `/health` |

3. **Environment** 里加 `HOST=0.0.0.0`、`SESSION_SECRET`（点 Generate）、`NODE_ENV=production`
4. Create Web Service

### 部署后验证

按顺序检查（都能通过才算成功）：

| # | 检查 | 期望 |
| --- | --- | --- |
| 1 | 打开 `https://<地址>/health` | `{"ok":true,"service":"course-selection-system",...}` |
| 2 | 打开首页 | 302 跳到登录页 |
| 3 | 用 `admin` / `123456` 登录 | 进入后台概览，课程 32 门、学生 12 人 |
| 4 | 用 `2024010101` / `123456` 登录 | 我的选课显示已选 4 门、13.0 学分 |
| 5 | 用 `T1001` / `123456` 登录 | 教师端提示 1 处授课冲突 |

## 五、免费版的三个限制（必须知道）

### 5.1 15 分钟无访问会休眠

| 现象 | 说明 |
| --- | --- |
| 15 分钟没有请求 | 服务自动休眠，不消耗免费时长 |
| 再次访问 | 冷启动 **30~60 秒**，期间浏览器显示 Render 的加载页 |
| 影响 | 答辩前先自己点一次"预热"，避免当众等待 |

每月 750 小时免费时长，单实例够用（休眠不计数）。

### 5.2 数据在每次唤醒后重置

免费版**没有持久磁盘**。休眠/重部署/重启后，本地文件系统恢复初始状态，
`data/course-selection.sqlite` 消失，下次启动由 `start:prod` 重新建库。

**这对课程演示反而是好事**：每次都是一份干净的演示数据，
不会出现"上一轮演示把某门课选满了"的尴尬。

**如果确实需要持久化**，两条路：

| 方案 | 做法 | 代价 |
| --- | --- | --- |
| 挂持久磁盘 | 升级到付费实例（$7/月起）后挂 Disk | 要付费 |
| 换数据库 | 改 `src/db/` 接 Render Postgres | 改动较大，超出本期范围 |

### 5.3 跨境访问偏慢

节点在新加坡，国内访问比本地慢，冷启动时更明显。
如果只是发给老师"点开看看"，可以接受；现场演示请用内网穿透做备份。

## 六、排错

| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| 构建失败 `Cannot find module` | 依赖没装全 | 看 Build Logs；确认 `package.json` 没被改坏 |
| 启动后 502 / 服务反复重启 | 启动命令报错（如端口没读环境变量） | 看 Logs；确认 `Start Command` 是 `npm run start:prod` |
| 打开首页 500 | 数据库没建成 | 看 Logs 里 `seed.js` 是否报错；确认 `data/` 可写 |
| 登录后立刻掉登录态 | 多实例 + 内存 session | 免费版单实例不会遇到；扩到多实例需改 session 存储 |
| 首次访问等很久 | 正常：冷启动 30~60 秒 | 提前预热 |

**看日志**：Render 控制台 → 服务 → **Logs**，`[warn]` 是用户走错路，`[error]` 才是故障。

## 七、本地与线上的一致性

| 项 | 本地 | Render |
| --- | --- | --- |
| 启动命令 | `npm start` 或双击 `start.bat` | `npm run start:prod` |
| 数据库 | 存在则复用 | 每次全新重建 |
| 端口 | 3000 或自动顺延 | 平台注入 |
| 会话密钥 | 开发默认值 | 随机生成 |

线上跑同一套代码、同一套测试逻辑；差异只在"数据库是否持久"，
不影响任何业务规则——`npm run smoke` 的 77 项断言在两种环境下都成立。
