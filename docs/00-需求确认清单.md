# 需求确认清单（定稿基线）

> 本文档记录选课系统需求决策，作为后续设计、开发与验收的**基线**。
> 确认时间：2026-10-16
> 确认方式：逐条与需求方确认，共 6 组 24 项

> **范围补充（2026-10-23）**：需求方追加管理员账号管理、管理员绕过选课窗口调整学生选课、
> 教师管理本人课程名单并为已选学生办理退课。补充项列于第六节，不改变原有学生自主注册不做、
> 课程容量与时间冲突规则，以及课程管理权限边界。

---

## 一、决策总表

### A. 系统角色与权限边界

| 编号 | 决策项 | 结论 | 说明 |
| --- | --- | --- | --- |
| A1~A3 | 角色范围 | **学生端 + 管理员端 + 教师端（三角色）** | 学生选课；管理员维护课程与选课窗口；教师查看自己所授课程的选课名单 |
| A4 | 登录方式 | **学号 + 密码，由管理员创建账号** | 不开放学生自主注册；管理员可创建学生/教师/管理员账号供系统使用 |

### B. 选课机制与时间窗口

| 编号 | 决策项 | 结论 | 说明 |
| --- | --- | --- | --- |
| B1 | 选课机制 | **先到先得 + 实时校验** | 提交即校验容量与时间冲突；不做志愿抽签、不做分轮次 |
| B2 | 选课时间窗口 | **需要，管理员可配置** | 管理员设置本轮选课的开放与截止时间；**窗口外禁止选课** |
| B3 | 退课时间限制 | **不做限制** | 退课不受选课窗口约束，任何时间均可退课 |
| B4 | 候补队列 | **做简单候补** | 课程满员后可加入候补；有名额释放时按候补顺序自动补位 |

### C. 时间冲突检查粒度

| 编号 | 决策项 | 结论 | 说明 |
| --- | --- | --- | --- |
| C1 | 基础粒度 | **星期 + 节次时间段** | 以「星期几 + 起止节次」描述上课时间 |
| C2 | 单双周 | **支持** | 课程时间表含周次字段，冲突判断时排除互不重叠的周次 |
| C3 | 相邻时段 | **不算冲突** | 仅当两个时间区间**真正重叠**才算冲突。<br>例：8:00~9:40 与 9:50~11:30 不算冲突 |
| C4 | 跨校区 | **不做** | 不引入校区维度 |

### D. 功能清单扩展

| 编号 | 决策项 | 结论 | 说明 |
| --- | --- | --- | --- |
| D1 | 学分统计与培养方案 | **不做** | 不引入培养方案模型 |
| D2 | 先修课检查 | **不做** | 选课不校验先修关系 |
| D3 | 选课日志审计 | **不做** | 不单独建操作审计表 |
| D4 | 导出课表 | **不做** | 不提供课表导出 |
| D5 | 公告通知 | **做** | 管理员发布选课相关公告，学生端与教师端可见 |
| D6 | 课程评价 | **不做** | 不提供评价打分功能 |

### E. 数据规模与并发

| 编号 | 决策项 | 结论 | 说明 |
| --- | --- | --- | --- |
| E1 | 数据规模 | **演示级** | 预置数十门课程、十余名学生、若干班级，覆盖全部演示场景 |
| E2 | 并发控制 | **数据库事务 + 选前一致性校验** | 保证「余量不超卖」 |
| E3 | 压力测试 | **编写并发压测脚本** | 模拟多人抢同一门课，验证不超容量，并在文档中给出实测数据 |

### F. 技术栈与交付

| 编号 | 决策项 | 结论 | 说明 |
| --- | --- | --- | --- |
| F1 | 技术栈 | **Node.js + Express + SQLite + 原生 HTML/CSS/JS** | 后端 Node.js + Express；数据库 SQLite（驱动用 `node-sqlite3-wasm`，纯 JS/WASM，**免原生编译**）；前端为服务端渲染页面 + 原生 HTML/CSS/JS，**不引入构建工具** |
| F2 | Docker 部署 | **不做** | 不提供 Dockerfile |
| F3 | 上线演示 | **要** | 除本地运行外，另生成在线演示链接 |
| F4 | 文档导出 | **Markdown + Word + PDF** | Markdown 入库存档，Word/PDF 用于提交 |

### 技术栈选型说明

| 选择 | 理由 |
| --- | --- |
| 后端 Node.js + Express | 前端本身就是 JavaScript，前后端**统一一门语言**，项目只需维护一套代码风格与依赖体系 |
| 数据库 SQLite | 整个数据库是**单个文件**，免安装、免配置、免常驻服务，拷贝文件即迁移全部数据；作业规模完全够用，也避免交作业时对方需另行安装数据库服务 |
| SQLite 驱动 `node-sqlite3-wasm` | 本机 Windows 环境**缺少 Visual Studio 原生编译工具链**，`better-sqlite3` 等需 `node-gyp` 编译的驱动必然失败；WASM 版为纯 JavaScript 实现，免编译即可用 |
| 前端原生 HTML/CSS/JS | 不引入构建工具（Webpack / Vite 等），**打开即跑**，演示环节最稳定，排查成本最低 |
| 不做 Docker | 本机未安装 Docker，无法实测验证；交付未经检验的配置没有意义 |

> 技术栈已由需求方确认，作为开发与文档的统一口径。

## 二、功能范围基线

### 2.1 本期实现（不做范围外扩展）

**核心功能（6 项）**
1. 课程查询
2. 选课
3. 退课
4. 人数限制
5. 时间冲突检查
6. 选课结果查询

**流程增强（2 项）**
7. 候补队列与自动补位
8. 公告通知

**支撑能力（3 项）**
9. 选课时间窗口配置（管理员）
10. 并发压测脚本
11. 教师端授课时间冲突提示

### 2.2 明确不做

- 志愿抽签、分轮次选课
- 学生自主注册
- 跨校区通勤冲突
- 学分统计与培养方案
- 先修课校验
- 选课日志审计
- 课表导出
- 课程评价
- Docker 部署

### 2.3 2026-10-23 需求补充

| 编号 | 功能 | 规则 |
| --- | --- | --- |
| D7 | 管理员账号管理 | 管理员可查询、创建学生/教师/管理员账号，编辑账号资料、重置密码；仅未被课程、选课或公告引用的账号可删除；禁止删除当前登录管理员。学生仍不能自主注册。 |
| D8 | 管理员调整学生选课 | 管理员可在选课窗口外为学生办理选课、已选退课或移出候补。加课仍校验课程状态、重复状态、时间冲突、容量和候补上限；满员时按既有规则入候补。已选退课仍触发候补补位。 |
| D9 | 教师管理本人课程名单 | 教师可从教师端查看本人所授课程和名单，并为本人课程中处于已选状态的学生办理退课；退课仍执行候补补位。教师不能修改课程信息，也不能操作他人课程或候补记录。 |

> 上述功能授权不新增数据库字段或角色。管理员代办只绕过选课窗口检查；容量、冲突、课程状态与候补规则保持有效。

## 三、按确认结果推导的补充规则

以下规则由上述决策**直接推导**得到，属于实现细节，无需额外确认；如有异议请提出。

| 编号 | 规则 |
| --- | --- |
| R1 | **候补顺序**：按加入候补的时间先后（FIFO），先到先得 |
| R2 | **候补容量**：候补队列人数上限等于课程容量（即最多再排一倍的候补） |
| R3 | **退课补位**：学生退课后，只要候补队列非空即自动补位队首学生，**不受选课窗口是否关闭影响** |
| R4 | **冲突判定**：两门课冲突 ⟺ 星期相同 **且** 节次区间重叠 **且** 周次集合有交集 |
| R5 | **单双周表示**：周次以「单周 / 双周 / 每周」三态表示，同时保存起始周与结束周 |
| R6 | **容量校验**：选课时先校验窗口状态，再校验是否已选、是否冲突，最后校验余量并占用名额，全程在单个事务内完成 |
| R7 | **教师端权限**：教师可查看**自己所授**课程的选课名单与人数，为本人课程中的已选学生办理退课，并获得「自己所授课程之间的时间冲突」提示；不可修改课程 |
| R8 | **管理员权限**：管理员可增删改课程（含容量、上课时间）、配置选课窗口、发布公告、管理账号，并在窗口外代办学生选课/退课（代办遵守课程状态、冲突、容量与候补规则） |
| R9 | **退课后重选**：学生退课失去名额后，可重新选同一门课，但须重新排入候补队列**队尾**，不允许插队 |

## 四、衍生细节确认结果

以下几项在最初的 24 项清单中未直接覆盖，已单独确认并落入上表规则：

| 编号 | 问题 | 结论 | 对应规则 |
| --- | --- | --- | --- |
| Q1 | 选课窗口关闭后，学生退课释放的名额要不要自动补位给候补？ | **照常自动补位**——候补补位不受窗口开关影响 | R3 |
| Q2 | 学生退掉一门课后，能否立即重新选上同一门课？ | **可以重选，但须排候补队尾**，不允许插队 | R9 |
| Q3 | 教师端要不要做「自己所授课程的时间冲突」提示？ | **要做**——教师可看到自己所授课程之间的冲突提示 | R7 |
